02트랙 A — 대학·기관

학사행정 · 공문 · 교원 연수

대학 행정의 병목은 대개 같은 자료를 여러 명이 각자 확인하는 일입니다. 제출 여부 세기, 명단 대조, 확인서 발급, 마감 독촉. 이 네 가지가 반복 업무의 8할입니다.

A-1 · 제출 명부 대조 → 미제출자에게만 메일

가장 먼저 자동화할 것. 대상 명부와 접수 명부를 비교해 미제출자에게만 메일을 보냅니다. 전체 공지 대신 개별 독촉이 되고, 담당자는 "누가 안 냈는지" 세지 않아도 됩니다.

Apps Script · 시트에 붙여 실행
/* A-1. 제출 명부 대조 → 미제출자 추출 → 담당자별 메일
   탭 [대상]  학과 | 과목코드 | 담당자 | 담당자메일
   탭 [접수]  과목코드 | 제출일시 | 파일링크
   트리거: 시간 기반 → 매일 오전 9시 → reportMissing */
function reportMissing() {
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const read = (name) => {
    const sh = ss.getSheetByName(name);
    if (!sh || sh.getLastRow() < 2) return [];
    return sh.getRange(2, 1, sh.getLastRow() - 1, sh.getLastColumn()).getValues();
  };

  const target = read('대상');   // [학과, 과목코드, 담당자, 담당자메일]
  const done = new Set(read('접수').map(r => String(r[0]).trim()));
  const missing = target.filter(r => !done.has(String(r[1]).trim()));

  const out = ss.getSheetByName('미제출') || ss.insertSheet('미제출');
  out.clearContents();
  out.getRange(1, 1, 1, 4).setValues([['학과', '과목코드', '담당자', '담당자메일']]);
  if (missing.length) out.getRange(2, 1, missing.length, 4).setValues(missing);

  const byMail = {};
  missing.forEach(r => {
    const key = String(r[3] || '').trim();
    if (!key) return;
    (byMail[key] = byMail[key] || []).push(r);
  });

  Object.keys(byMail).forEach(mail => {
    const list = byMail[mail].map(r => '- ' + r[0] + ' / ' + r[1]).join('\n');
    MailApp.sendEmail({
      to: mail,
      subject: '[미제출] ' + byMail[mail].length + '건 — 마감 전 확인 부탁드립니다',
      body: list + '\n\n집계: ' + Utilities.formatDate(new Date(), 'Asia/Seoul', 'yyyy-MM-dd HH:mm')
    });
  });

  return missing.length;
}

포인트는 Set 한 줄입니다. 엑셀 함수로 하던 일을 코드로 옮기면, 조건이 바뀌어도 한 곳만 고치면 됩니다.

A-2 · 접수 즉시 확인서 PDF 발급

구글 문서 템플릿에 {{이름}} 같은 자리를 만들어 두고, 양식이 접수되면 그 자리만 바꿔 PDF로 보냅니다. 확인서·수료증·공문 초안이 모두 같은 구조입니다.

Apps Script · 양식 제출 트리거
/* A-2. 폼 접수 → 확인서 PDF → 신청자 메일
   준비 1) 구글 문서 템플릿에 {{이름}} {{소속}} {{접수일}} 을 넣고 ID를 적습니다
   준비 2) 보관 폴더를 만들고 ID를 적습니다
   트리거: 스프레드시트 → 양식 제출 시 → onSubmit */
const TEMPLATE_ID = '구글문서_템플릿_ID';
const ARCHIVE_ID  = '보관_폴더_ID';

function onSubmit(e) {
  const v = e.namedValues;
  const name = (v['이름'] || [''])[0].trim();
  const org  = (v['소속'] || [''])[0].trim();
  const mail = (v['이메일'] || [''])[0].trim();
  if (!mail) return;

  const copy = DriveApp.getFileById(TEMPLATE_ID).makeCopy('확인서_' + name);
  const doc = DocumentApp.openById(copy.getId());
  const body = doc.getBody();
  body.replaceText('{{이름}}', name);
  body.replaceText('{{소속}}', org);
  body.replaceText('{{접수일}}', Utilities.formatDate(new Date(), 'Asia/Seoul', 'yyyy년 M월 d일'));
  doc.saveAndClose();

  MailApp.sendEmail({
    to: mail,
    subject: '[접수확인] ' + name + '님 신청이 접수되었습니다',
    body: name + '님, 신청이 접수되었습니다. 확인서를 첨부합니다.\n\n' + org,
    attachments: [copy.getAs(MimeType.PDF)]
  });

  copy.moveTo(DriveApp.getFolderById(ARCHIVE_ID));
}
주의 — 확인서에 성적·주민번호·진단명 같은 민감정보가 들어가면, 첨부 메일은 반드시 본인 주소로만 보내고 보관 폴더 공유 범위를 확인하세요. 이 한 줄이 사고를 막습니다.

03트랙 B — 센터·병원

예약 · 기록 · 매출

센터의 병목은 상담이 아니라 기록과 알림입니다. 예약을 받아 적고, 전날 다시 확인하고, 월말에 매출을 세는 일. 이 세 가지가 원장·수첩·머릿속에 흩어져 있으면 회원이 늘어날수록 무너집니다.

B-1 · 내일 예약자에게만 전날 알림

노쇼를 줄이는 가장 값싼 방법은 알림입니다. 전날 저녁 6시에 내일 예약자에게만 메일을 보냅니다. 취소·완료 상태는 건너뜁니다.

Apps Script · 시트에 붙여 실행
/* B-1. 내일 예약자에게 전날 알림
   탭 [예약]  예약일 | 시간 | 이름 | 연락처 | 이메일 | 상태
   트리거: 시간 기반 → 매일 오후 6시 → remindTomorrow */
const CENTER = '한별 필라테스';

function remindTomorrow() {
  const sh = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('예약');
  if (!sh || sh.getLastRow() < 2) return 0;

  const rows = sh.getRange(2, 1, sh.getLastRow() - 1, 6).getValues();
  const tomorrow = Utilities.formatDate(new Date(Date.now() + 86400000), 'Asia/Seoul', 'yyyy-MM-dd');
  let sent = 0;

  rows.forEach((r, i) => {
    const day = r[0] instanceof Date
      ? Utilities.formatDate(r[0], 'Asia/Seoul', 'yyyy-MM-dd')
      : String(r[0]).trim();
    if (day !== tomorrow) return;

    const mail = String(r[4] || '').trim();
    const state = String(r[5] || '').trim();
    if (!mail || state === '취소' || state === '완료') return;

    MailApp.sendEmail({
      to: mail,
      subject: '[예약 안내] 내일 ' + r[1] + ' ' + r[2] + '님 예약',
      body: r[2] + '님, 내일(' + tomorrow + ') ' + r[1] + ' 예약이 있습니다.\n' +
            '오실 수 없으시면 이 메일에 회신해 주세요.\n\n' + CENTER + ' 드림'
    });

    sh.getRange(i + 2, 6).setValue('알림발송');
    sent++;
  });

  return sent;
}

B-2 · 월 마감 요약을 메일로

매월 1일 아침에 지난달 매출과 건수를 요약해 자기 메일로 보냅니다. 회계 프로그램을 바꾸지 않아도 됩니다. 쓰던 시트에 열만 맞추면 됩니다.

Apps Script · 시트에 붙여 실행
/* B-2. 지난달 매출 요약 → 메일
   탭 [매출]  날짜 | 회원 | 구분 | 금액
   트리거: 시간 기반 → 월 단위 → 매월 1일 오전 10시 → monthSummary */
function monthSummary() {
  const sh = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('매출');
  if (!sh || sh.getLastRow() < 2) return 0;

  const rows = sh.getRange(2, 1, sh.getLastRow() - 1, 4).getValues();
  const first = new Date();
  first.setDate(1);
  first.setMonth(first.getMonth() - 1);
  const ym = Utilities.formatDate(first, 'Asia/Seoul', 'yyyy-MM');

  let sum = 0, count = 0;
  const byKind = {};

  rows.forEach(r => {
    const d = r[0] instanceof Date ? r[0] : new Date(r[0]);
    if (isNaN(d.getTime())) return;
    if (Utilities.formatDate(d, 'Asia/Seoul', 'yyyy-MM') !== ym) return;
    const amount = Number(String(r[3]).replace(/[^0-9-]/g, '')) || 0;
    sum += amount;
    count++;
    const k = String(r[2] || '기타').trim() || '기타';
    byKind[k] = (byKind[k] || 0) + amount;
  });

  const lines = Object.keys(byKind)
    .sort((a, b) => byKind[b] - byKind[a])
    .map(k => '- ' + k + ': ' + byKind[k].toLocaleString('ko-KR') + '원')
    .join('\n');

  MailApp.sendEmail({
    to: Session.getActiveUser().getEmail(),
    subject: '[' + ym + '] 매출 마감 — ' + sum.toLocaleString('ko-KR') + '원 / ' + count + '건',
    body: ym + ' 마감 요약\n\n합계: ' + sum.toLocaleString('ko-KR') + '원 (' + count + '건)\n\n' + lines
  });

  return sum;
}
숫자에 대한 규칙 — 매출·재등록률·성과 수치는 AI에게 계산시키지 않습니다. 원자료 시트에서 코드로만 합산합니다. AI가 만든 숫자가 보고서에 한 번 들어가면, 그 뒤의 모든 숫자를 믿을 수 없게 됩니다.

P1 · 병목 정의 (1일차)
나는 [소속]에서 [업무]를 맡고 있다.
지금 이 업무는 [누가] [무엇을] [얼마나 자주] 반복한다.

이 업무를 자동화하려고 한다. 바로 코드를 쓰지 말고, 먼저 다음 3개를 물어봐라.
1) 이 업무에서 사람이 반드시 판정해야 하는 지점은 어디인가
2) 자동화하면 안 되는 부분은 무엇인가
3) 무엇을 측정하면 개선됐는지 알 수 있는가
내 답을 받은 뒤에 설계를 제안해라.
P2 · 데이터 구조 (2일차)
이 업무에 필요한 데이터를 구글 시트 한 장으로 설계해라.
조건:
- 열은 8개 이하
- 사람이 손으로 채우는 열과 프로그램이 채우는 열을 구분해서 표시
- 날짜·시간 열은 시간대를 Asia/Seoul로 고정
- 중복 판정에 쓸 열을 하나 정하고 이유를 설명

먼저 표로 보여주고, 내가 승인한 뒤에만 Apps Script 코드를 써라.

아래 코드를 배포하기 전에, 이 코드가 조용히 잘못될 수 있는 경우를 10개 찾아라.
각 항목마다 (1) 어떤 입력에서 (2) 무엇이 잘못되고 (3) 사용자는 그것을 알아챌 수 있는지 적어라.
그 다음, 그 10개 중 실제로 확인할 수 있는 것만 골라 테스트 코드를 써라.
"문제 없습니다"라고 먼저 말하지 마라.

P4 · 화면 — 버튼 두 개 원칙 (4일차)
이 자동화를 쓰는 사람은 [누구]이고, 컴퓨터를 잘 모른다.
화면을 하나만 만들어라. 조건:
- 첫 화면에서 할 수 있는 동작은 2개 이하 (예: 확인 / 취소)

- 휴대폰 세로 화면에서 먼저 확인해라
P5 · 권한과 개인정보
이 시스템에 들어가는 개인정보를 목록으로 정리해라.

필요 없다고 판단한 항목은 수집하지 않는 설계로 바꿔라.
그 다음, 권한을 역할 3개(입력하는 사람 / 보는 사람 / 관리자)로 나눈 표를 만들어라.

이 자동화를 배포하기 전에 되돌리는 절차를 먼저 만들어라.
1) 배포 전에 무엇을 백업하는가 (파일·시트·설정)
2) 잘못됐을 때 끄는 방법 (트리거 삭제·배포 중지)
3) 데이터가 잘못 들어갔을 때 복원 순서
4) 되돌린 뒤 무엇을 확인하는가
절차를 5줄 이내로 쓰고, 그 절차를 코드 주석 맨 위에 넣어라.

A-P1 · 판정 기준을 코드로
강의계획서에서 "AI 관련 내용이 4주 이상"인지 판정해야 한다.
판정 기준을 내가 말로 설명하겠다. [기준 설명]
이 기준을 코드로 옮겨라. 단:
- 판정 결과는 통과 / 미비 / 판단불가 3가지로만 나눈다
- 판단불가는 사람에게 넘긴다 (프로그램이 임의로 통과시키지 않는다)
- 왜 그렇게 판정했는지 근거 문장을 함께 저장한다
- 기준을 바꾸면 과거 판정을 다시 계산할 수 있는 구조로 만든다
A-P2 · 골든 템플릿 역주입
완성된 문서 한 부를 '골든 템플릿'으로 쓰려고 한다.
이 문서 구조를 분석해서, 학과마다 바뀌는 부분(글자·표 행)과 절대 바뀌면 안 되는 부분(양식·조항·서식)을 나눠 표로 정리해라.
그 다음, 바뀌는 부분만 데이터로 채우는 코드를 써라.
표는 행을 늘릴 수 있는 것과 없는 것을 구분해서 알려 달라. 없는 표에 행을 넣으면 서식이 깨진다.
A-P3 · 집계표와 요약 메일
아래 시트 구조에서 학과별 제출 현황을 집계해 담당자에게 보낼 요약 메일을 만들어라.
조건:
- 전체 발송이 아니라 미제출자에게만, 담당자별로 묶어서 보낸다
- 메일 본문은 5줄 이내, 목록은 '- 학과 / 과목코드' 형식
- 숫자는 시트에서 계산한 값만 쓴다
- 집계 시각을 Asia/Seoul로 명시한다
[시트 구조 붙여넣기]

트랙 B 전용 3개

B-P1 · 예약·노쇼 기록 구조
필라테스·재활센터의 예약과 방문을 한 시트로 관리하려고 한다.
열 8개 이하로 설계해라. 조건:
- 예약과 실제 방문(노쇼·취소·완료)을 구분할 수 있어야 한다
- 노쇼율을 월별로 계산할 수 있어야 한다
- 연락처·이메일은 알림에만 쓰고 다른 곳에 복사하지 않는다
- 나중에 회원별 방문 이력을 뽑을 수 있는 키를 정해라
표로 먼저 보여주고 승인을 받아라.
B-P2 · 기록 문장 생성 규칙
상담·운동 기록을 남길 때 쓰는 문장 형식을 정하려고 한다.
아래는 내가 실제로 쓰는 표현이다. [예시 3개]
이 표현을 유지하면서, 측정값을 넣으면 문장이 완성되는 규칙을 만들어라.
조건:
- 진단명이나 추정 병명을 AI가 새로 쓰지 않는다 (내가 입력한 것만 쓴다)
- 수치는 입력값만 그대로 쓴다 (계산·추정 금지)
- 문장은 2줄 이내
- 회원이 읽어도 불편하지 않은 표현으로 쓴다
B-P3 · 월 매출·재등록 요약
아래 매출 시트에서 지난달 요약을 만들려고 한다.
항목: 총매출 / 건수 / 구분별 합계 / 재등록률 / 신규 회원 수.
조건:
- 모든 숫자는 시트 값에서만 계산한다 (추정·보정 금지)
- 값이 없는 항목은 0이 아니라 '자료 없음'으로 표시한다
- 요약 결과를 메일 본문으로 보낼 수 있게 10줄 이내 텍스트로 만든다
[시트 구조 붙여넣기]

  2. 실패했을 때 사용자가 알아챌 수 있다. (조용히 잘못되는 경로가 없다)
