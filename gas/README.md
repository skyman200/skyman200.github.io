# 인피니티 퍼널 백엔드 (Google Apps Script)

홈페이지 신청 폼·유입 랜딩(`/go/`) → `인피니티퍼널_DB` 시트 `DB` 탭 저장 → 1·3·5·7·14·30일차 메일 자동 발송.
상담·프로젝트 신청(`/apply/`) → 같은 시트 `상담신청` 탭 저장 → 관리자 알림.
집계는 시트 수식만으로(`대시보드` 탭), 메타 맞춤타겟 명단은 `exportMetaAudienceCsv()` 로 뽑습니다.
서버비 0원: GitHub Pages(앞) + Apps Script(뒤) + Google Sheets(DB).

## 남은 단계는 하나입니다 (계정 주인만 할 수 있는 승인)

시트 생성 · 머리글 · 서식 · 트리거는 `setup()` 이 알아서 만듭니다.
사람이 직접 해야 하는 것은 **Apps Script 프로젝트를 열고 승인·배포하는 일** 하나입니다.

1. https://script.google.com → 새 프로젝트 → 이름 `인피니티퍼널`
   (**권장: `ptkanghoon@gmail.com` 계정으로 만드세요.** 발신 주소가 이 계정이 되고, Gmail→Gmail은 스팸 판정이 가장 약합니다.)
2. 편집기의 기본 코드를 지우고 이 폴더의 `Code.gs` → `MailTemplates.gs` 순서로 붙여넣기
   (파일이 하나뿐이면 `+` → 스크립트로 `MailTemplates` 를 하나 더 만들고 붙여넣습니다)
3. 프로젝트 설정 → `appsscript.json` 매니페스트 표시를 켜고 이 폴더의 내용으로 교체
   (웹앱 액세스 권한이 `모든 사용자`로 잡히는 부분입니다)
4. 함수 선택에서 `setup` → 실행 → 권한 검토 → 계정 선택 → "고급" → "이동" → 허용
   (스프레드시트·메일 발송 권한입니다. 실행 로그에 시트 주소가 찍힙니다)
5. 배포 → 새 배포 → 유형 `웹앱` → 실행 계정 `나` / 액세스 권한 `모든 사용자` → 배포
6. 나온 **웹앱 URL**(`https://script.google.com/macros/s/.../exec`)을
   `funnel/funnel.js` 의 `endpoint` 값에 붙여넣고 커밋 → 끝

> 5번까지는 Google 계정 주인의 승인 화면이라 대신 눌러 드릴 수 없습니다. 6번은 30초입니다.

## 3단계 코드로 바꿀 때 (지금 배포된 프로젝트 — 14·30일차 · 대시보드 · 맞춤타겟)

1. 편집기에서 `Code.gs` · `MailTemplates.gs` 를 **새 내용으로 통째로 교체**합니다(일부만 붙이면 `STAGES`·`nextStage_` 가 없어집니다).
2. `setup()` 을 **한 번 다시 실행**합니다. 기존 `DB`·`상담신청` 행은 그대로 두고 `대시보드` 탭이 새로 만들어집니다.
3. 배포 → **배포 관리** → 기존 배포 옆 연필 → 버전 `새 버전` → 배포. (URL 그대로라 `funnel.js` 는 손대지 않습니다)
4. `previewMail('내 메일', 14)` · `previewMail('내 메일', 30)` 으로 새 메일 두 통을 먼저 확인합니다.
5. `exportMetaAudienceCsv()` 를 실행해 `맞춤타겟` 탭이 만들어지는지 확인합니다.

| 항목 | 바뀐 것 |
| --- | --- |
| 시퀀스 | 7일에서 끝나지 않고 **14일차(돌아간 것 3개)**, **30일차(한 달 점검·다음 것)** 가 이어집니다 |
| 상태 | 7일차에 `완료`로 바꾸던 것을 **30일차에만** `완료`로 바꿈 |
| 무한 루프 | `완료`·`수신거부` 상태에서 **다시 신청하면 1일차부터 재시작**(1일차 메일 재발송) |
| 대시보드 | `대시보드` 탭 — 총 DB, 오늘·이번 주·이번 달 신규, 소속·관심·채널·단계별, 상담 전환율, 공유 유입 |
| 맞춤타겟 | `exportMetaAudienceCsv()` — 수신거부·중복·형식오류를 뺀 이메일 명단 |

## 무한 루프가 도는 자리 (3단계)

```
/go/ · #kit · 칼럼 배너 → DB
   └ 1 → 3 → 5 → 7 → 14 → 30일차     (30일차에 상태=완료, 자동 발송 중지)
        30일차 메일: 한 달 점검 3문항 + /apply/ 안내 + "다시 신청하면 1일차부터"
   └ 다시 신청(같은 주소) → 단계 1 · 상태 활성 · 1일차 재발송  ↺
   └ /apply/ → 상담신청 탭 → 관리자 알림(회신은 사람이) → 필요하면 시퀀스 재시작
```

한 번에 한 단계만 내보냅니다. 오랜 공백(할당량·휴직 등) 뒤에 메일 다섯 통이 몰려 나가지 않게 하려는 것입니다.

## 대시보드 탭 (3단계)

`setup()` 또는 `rebuildDashboard()` 가 다시 그립니다. **숫자는 전부 시트 수식**이라 트리거·할당량·실행 기록이 늘지 않습니다.

| 구역 | 계산 |
| --- | --- |
| 요약 | 총 DB `COUNTA` · 활성 · 오늘 신규 · 이번 주 신규(월~일, `WEEKDAY(...,3)`) · 이번 달 신규(`EOMONTH`) · 상담신청 수 · 상담 전환율(`COUNTUNIQUE`/`COUNTA`) · 수신거부 · 7일차·30일차 도달 · 공유 유입(`*ref=share*`) |
| 소속유형별 | `QUERY(DB!$A$2:$J, "select D, count(D) ... group by D")` |
| 관심분야별 | `QUERY ... select E ...` |
| 유입 채널 | `/go/` · 홈 `#kit` · `/starter-kit/` · `vibe-coding` · `/apply/` · 그 외 — `COUNTIF` 패턴(`*/go/*` 등) |
| 시퀀스 단계별 | `QUERY ... select G ...` — 1·3·5·7·14·30 에 몇 명이 도달했는지 |
| 상담 트랙별 | `QUERY('상담신청'!...)` |
| 최근 7일 | `QUERY ... group by toDate(A) order by ... desc limit 7` |

`유입경로` 열은 폼이 보낸 경로+쿼리+리퍼러를 **원문 그대로** 저장합니다(`/go/?utm_source=threads ← t.co`).
그래서 채널은 `*패턴*` 으로 셉니다. 채널 분류를 바꾸려면 `ensureDashboard_` 의 COUNTIF 패턴을 고치세요.
합계가 안 맞을 때는 `그 외 · 직접` 행을 보세요 — 그 행이 0보다 크면 어딘가에서 새 경로로 들어온 것입니다.

## 메타 맞춤타겟 (3단계 — SNS 정지 대비)

박영재 대표 전략의 핵심은 “팔로워가 아니라 내가 가진 명단으로 다시 도달한다”입니다. SNS 계정이 멈춰도
이메일 DB는 남습니다. 그 명단을 메타 광고의 **맞춤 타겟(Custom Audience)** 으로 올려 두면 비슷한 사람에게 다시 닿을 수 있습니다.

1. 편집기에서 `exportMetaAudienceCsv()` 실행 (이름까지 필요하면 `exportMetaAudienceCsv(true)`)
2. `맞춤타겟` 탭이 새로 만들어집니다 — `email` · `이름` · `상태` · `유입경로`
3. 시트에서 **파일 > 다운로드 > 쉼표로 구분된 값(.csv)** 로 저장
4. 메타 광고 관리자 > 대상(Audiences) > 고객 목록 > CSV 업로드 → 식별자 열로 `email` 지정
5. 갱신은 한 달에 한 번이면 충분합니다(같은 파일을 다시 올리면 목록이 갱신됩니다)

빠지는 사람: `수신거부`, 이메일 형식 오류, 중복(소문자 기준 첫 행만). 반환값이 곧 CSV 문자열이라
필요하면 다른 곳에 그대로 붙여 넣어도 됩니다.

> **왜 Drive 파일을 만들지 않나** — `DriveApp` 을 쓰면 계정 주인이 승인 화면을 한 번 더 눌러야 합니다.
> 그 한 번이 배포를 막는 일이 생겨서, 권한을 늘리지 않는 쪽(탭 + CSV 다운로드)으로 만들었습니다.

## 시트 구조

| 탭 | 열 |
| --- | --- |
| `DB` | 일시 · 이름 · 이메일 · 소속유형 · 관심분야 · 유입경로 · 시퀀스단계 · 상태 · 최근발송 · 메모 |
| `상담신청` | 일시 · 이름 · 이메일 · 연락처 · 소속유형 · 소속명 · 희망트랙 · 반복업무 · 지금걸리는시간 · 희망시기 · 예산범위 · 유입경로 · 상태 · 메모 |
| `설정` | 아래 표 |
| `발송로그` | 일시 · 이메일 · 단계 · 제목 · 결과 |
| `대시보드` | 수식만 있는 집계 화면(`setup()`·`rebuildDashboard()` 가 다시 그림) |
| `맞춤타겟` | `exportMetaAudienceCsv()` 실행 때마다 다시 쓰는 내보내기(email·이름·상태·유입경로) |

`상담신청`의 `상태`는 `신규 · 회신완료 · 상담중 · 진행 · 보류 · 거절` 중에서 고르면 됩니다.
`반복업무` 열은 줄바꿈이 켜져 있어 신청서 원문이 그대로 읽힙니다.

## 설정 탭에서 코드 없이 고치는 값

`발신자이름` · `회신주소` · `사이트주소` · `스타터키트주소` · `5일차영상주소`(비우면 영상 없이 발송)
· `7일차진단주소` · `관리자메일` · `관리자알림`(Y/N) · `상담알림`(Y/N) · `시퀀스발송시각`(0~23)

`5일차영상주소`에 유튜브 링크를 넣으면 그날 메일이 "영상 준비 중" 대신 영상 링크로 나갑니다.

## 손으로 쓰는 함수

- `setup()` — 최초 1회, 또는 코드 교체 후 1회. 시트·탭·설정·대시보드·트리거 정리
- `setSpreadsheetId('시트ID')` — 이미 만든 시트를 쓰고 싶을 때
- `previewMail('내메일@주소', 3)` — 해당 일차 메일 문구를 나에게만 먼저 보내 확인 (`1`·`3`·`5`·`7`·`14`·`30`)
- `rebuildDashboard()` — `대시보드` 탭 수식을 코드 기준으로 다시 그림
- `exportMetaAudienceCsv()` / `exportMetaAudienceCsv(true)` — 메타 맞춤타겟 명단 추출(CSV 문자열 반환)
- `resendWelcome()` — 1일차 발송이 실패한 사람에게 다시 발송
- `processSequence()` — 트리거를 기다리지 않고 지금 한 번 돌려 보기

스프레드시트에 붙인(컨테이너 바인딩) 프로젝트라면 메뉴 `인피니티 퍼널` 에 세 항목이 생깁니다.
스탠드얼론 프로젝트(script.google.com 에서 새로 만든 것)는 메뉴가 안 보이는 게 정상이고, 위 함수를 편집기에서 실행하면 됩니다.

## 배포 직후 확인 3줄

1. 편집기에서 `previewMail('본인메일', 1)` → 편지형 1일차 메일이 받은편지함(스팸 아님)으로 오는지. 이어서 `14`·`30`도 한 번씩.
2. `/go/` 에서 직접 한 번 신청 → `DB`에 한 줄, 웰컴 메일, 관리자 알림 도착 확인 → `대시보드` 탭의 `총 DB 수`가 1인지.
3. `/apply/` 에서 한 번 신청 → `상담신청`에 한 줄, 관리자 알림에 연락처·반복업무가 그대로 있는지 → `상담 전환율`이 0%가 아닌지.

3·5·7·14·30일차는 다음 날 오전 9시 트리거부터 나가므로, 급하면 `processSequence()`를 직접 돌려 보세요(발송 시각 조건 때문에 그 시각에만 나갑니다 — 확인용으로는 `previewMail`이 빠릅니다).

## 한도

Apps Script 무료(개인 @gmail) 계정은 하루 100명까지 메일 발송입니다(`MailApp.getRemainingDailyQuota()`).
`processSequence` 는 한 번에 최대 40명까지만 내보내 스팸 평판을 지킵니다. 하루 신청이 100명을 넘으면
Workspace 계정(1,500명/일)으로 옮기거나 그날 남은 사람은 다음 날로 넘어갑니다.

시퀀스가 6단계로 늘었으니 한 사람당 메일은 6통(1·3·5·7·14·30일 시점)입니다.
무료 한도는 “그날 보낼 사람 수” 기준이라 14·30일차가 몰려도 하루 40명 상한 안에서만 나갑니다.
