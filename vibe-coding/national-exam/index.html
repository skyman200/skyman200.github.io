VIBE CODING CASE 07 · SMART CAMPUS

[바이브 코딩 7편] "공부해야 문이 열립니다" — 국가고시 100% 합격을 위한 DIT 국시실 스마트 출결 & 5문항 퀴즈 입실 시스템 구축기

출석만 찍고 사라지는 자습실의 종말. 지오펜싱 위치 인증, 1,139문항 기반 개인화 취약 영역 AI 퀴즈 엔진, 실시간 합격 위험도 예측 대시보드까지 서버비 0원으로 구축한 실전 기록.

작성자: 김강훈 교수 (동의과학대학교 물리치료과 학과장 / DIT AI 허브센터 팀장)
발행일: 2026년 11월 13일
읽는 시간: 약 7분

1. 프롤로그: "교수님, 출석 도장만 찍고 나가는 건 어떻게 막나요?"

매년 12월 셋째 주, 전국 3년제·4년제 대학 물리치료과 수험생들이 한국보건의료인국가시험원(국시원)이 주관하는 국가고시에 응시합니다. 학과장으로서 학생들의 국가고시 100% 합격은 양보할 수 없는 지상 과제입니다. 매년 9월부터 학과에서는 3학년 전용 자습실인 'DIT 국시실'을 열고 야간 자율학습과 모의고사 집중 체제를 가동합니다.

하지만 모든 대학의 고시반이 겪는 고질적인 병목이 있었습니다.

  • 무늬만 출석: 입실 지문이나 대장 서명만 하고 5분 뒤 카페나 밖으로 나가버리는 학생.
  • 대리 태그: 친구의 학생증이나 모바일 화면을 캡처해 대신 찍어주는 행위.
  • 맹목적 자습: 책상에 6시간 앉아 있었지만, 정작 자신이 모의고사에서 과락을 맞는 단원(의료법규, 신경계 중재, 보조기구학 등)은 손도 안 대고 아는 내용만 반복해 읽는 비효율.
"출결 관리 솔루션 견적을 내보니 시스템 구축에만 1,500만 원, 전용 태블릿과 리더기 유지보수에 연 수백만 원이 든다고 했습니다. 학과 예산으로 감당할 수도 없거니와, 그 기계들도 '출석'만 체크할 뿐 '공부'를 시키지는 못했습니다."

그래서 결심했습니다. "문이 열리기 전에, 학생에게 반드시 필요한 공부를 시키자. 문제를 맞춰야만 입실이 승인되는 자습실을 직접 만들자."

비개발자인 제가 클로드(Claude)와 커서(Cursor)를 켜고 바이브 코딩으로 단 사흘 만에 구축해 현장에 투입한 'DIT 국시실 스마트 출결 & 퀴즈 엔진'의 풀스택 아키텍처를 공개합니다.

2. 전체 아키텍처: 3단 인터락(Interlock) 진입 파이프라인

시스템의 핵심 철학은 "출석은 결과가 아니라 학습의 통과 의례"라는 점입니다. 학생이 국시실 문 앞에 서서 문을 열기까지 3단계의 하드웨어·소프트웨어 인터락이 작동합니다.

[학생 스마트폰 (PWA)] │ ▼ (1단계: 물리적 접근 검증) [반경 20m 지오펜싱(GPS) + 30초 동적 TOTP QR 스캔] - 캠퍼스 밖/원격 대리 인증 원천 차단 │ ▼ (2단계: 적응형 인텔리전트 퀴즈) [개인화 취약 영역 5문항 퀴즈 출제] - 1,139개 국시 기출 은행에서 개인별 정답률 60% 미만 과목 자동 추출 - 4문항 이상 정답 시: 입실 승인 토큰 발급 & 도어락 웹훅 해제 - 불합격 시: 5분간 오답 해설 열람 강제 락 → 재응시 │ ▼ (3단계: 교수자 관제 대시보드) [실시간 합격 예측 레이더 (Supabase + Next.js)] - 누적 순수 학습 체류 시간 × 퀴즈 정답률 = 합격 위험군(Danger) 즉각 알림

3. 병목 1: "집에서 찍는 QR"을 원천 차단한 지오펜싱 + 동적 TOTP 하이브리드

시중 대학 전자출결 앱의 최대 맹점은 QR 코드를 스크린샷 찍어 카카오톡으로 보내면 도서관 밖에서도 출석이 인정된다는 점이었습니다.

이를 막기 위해 브라우저의 navigator.geolocation API와 서버 측 30초 단위 TOTP(시간 기반 일회용 패스워드)를 결합했습니다.

// geofence-validator.ts: 반경 20m 하버사인 공식 검증
export function isWithinExamRoom(userLat: number, userLng: number): boolean {
  const EXAM_ROOM_LAT = 35.168542; // 동의과학대 석당관 4층 국시실 위도
  const EXAM_ROOM_LNG = 129.071285; // 국시실 경도
  const MAX_RADIUS_METERS = 20;     // 허용 오차 반경 20m

  const R = 6371e3; // 지구 반경 (m)
  const dLat = (userLat - EXAM_ROOM_LAT) * (Math.PI / 180);
  const dLng = (userLng - EXAM_ROOM_LNG) * (Math.PI / 180);

  const a = Math.sin(dLat / 2) * Math.sin(dLat / 2) +
            Math.cos(EXAM_ROOM_LAT * (Math.PI / 180)) * 
            Math.cos(userLat * (Math.PI / 180)) *
            Math.sin(dLng / 2) * Math.sin(dLng / 2);
  const c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
  const distance = R * c;

  return distance <= MAX_RADIUS_METERS;
}

국시실 출입문 옆에 비치된 저가형 태블릿(안드로이드 공기계) 화면에는 30초마다 갱신되는 동적 TOTP 기반 QR 코드가 표시됩니다. 학생은 ①국시실 문 앞 20m 이내에 도달한 상태에서, ②지금 화면에 떠 있는 30초 유효 QR을 스캔해야만 다음 단계인 퀴즈 화면으로 넘어갈 수 있습니다. 캡처본 공유를 통한 대리 출석은 0%로 떨어졌습니다.

4. 병목 2: 1,139개 기출 데이터베이스와 '취약 영역 타깃 퀴즈' 엔진

출석만 찍히고 끝난다면 기존 출결 앱과 다를 바가 없습니다. 이 시스템의 진짜 마법은 입실 퀴즈에 있습니다.

학과 학생들의 최근 3회분 전국 모의고사 성적표 데이터를 익명화하여 Supabase DB에 적재했습니다. 학생마다 구멍 난 과목이 다릅니다. 어떤 학생은 '의료관계법규'가 과락 위기이고, 어떤 학생은 '신경계 물리치료학' 점수가 낮습니다.

"학생이 문 앞에 서서 QR을 찍는 순간, 시스템은 그 학생의 가장 취약한 하위 단원을 조회해 5문항의 기출 변형 문제를 무작위로 추출합니다."

💡 국시실 입실 퀴즈 규칙

• 문항 수: 5문항 (문항당 45초 타임어택 제한)
• 출제 로직: 최근 모의고사 정답률 60% 미만 과목 3문항 + 전범위 핵심 빈출 2문항
• 합격 기준: 4문항(80점) 이상 정답 시 즉시 [입실 승인]
• 불합격 시 패널티: 틀린 문항의 상세 해설과 필수 암기 카드가 강제로 5분간 노출되며, 5분이 지나야 재도전 가능

처음에는 "문 앞에서 문제 푸느라 줄 서면 어떡하냐"는 우려가 있었습니다. 하지만 1주일이 지나자 놀라운 변화가 생겼습니다. 학생들이 국시실에 도착하기 전 계단을 올라오며 모바일로 미리 약점 암기 카드를 열람하고, 문 앞에서는 2분 만에 집중해서 문제를 풀고 당당하게 문을 열고 들어가는 '입실 전 웜업 루틴'이 정착된 것입니다.

5. 병목 3: "누가 떨어질 것인가?" — 교수의 밤잠을 깨우는 합격 예측 레이더

교수에게 가장 절박한 정보는 "지금 누가 자습실에 있는가"가 아니라, "12월 국시에서 과락 위험이 있는 학생이 누구인가"입니다.

기존에는 한 달에 한 번 치르는 종이 모의고사 성적이 나올 때까지 학생의 위기를 알 수 없었습니다. 하지만 국시실 스마트 출결 시스템은 매일매일의 '순수 체류 시간'과 '일일 취약점 퀴즈 정답률'을 실시간 누적합니다.

-- pass-risk-calculator: 실시간 합격 위험 지수 계산 뷰
CREATE OR REPLACE VIEW student_exam_risk AS
SELECT 
  s.student_id,
  s.name,
  COALESCE(SUM(a.duration_minutes), 0) as total_study_minutes,
  ROUND(AVG(q.score), 1) as avg_quiz_score,
  CASE 
    WHEN AVG(q.score) < 60 OR COALESCE(SUM(a.duration_minutes), 0) < 1200 THEN 'DANGER (과락위험군)'
    WHEN AVG(q.score) < 75 OR COALESCE(SUM(a.duration_minutes), 0) < 2400 THEN 'WARNING (집중관리군)'
    ELSE 'SAFE (안정권)'
  END as risk_level
FROM students s
LEFT JOIN attendances a ON s.id = a.student_id AND a.created_at >= NOW() - INTERVAL '14 days'
LEFT JOIN quiz_logs q ON s.id = q.student_id AND q.created_at >= NOW() - INTERVAL '14 days'
GROUP BY s.student_id, s.name;

이 지표는 교수 전용 모바일 대시보드에 실시간으로 표시됩니다. 최근 2주간 자습 시간이 급감했거나, 퀴즈 정답률이 60점 미만으로 떨어진 학생이 감지되면 디스코드(Discord) 봇이 학과장인 저에게 비공개 알림을 전송합니다. 성적이 완전히 곤두박질치기 전에, 교수가 먼저 연구실로 학생을 불러 따뜻한 차 한 잔을 건네며 상담할 수 있는 '골든타임'을 확보한 것입니다.

6. 학생 자생적 프로젝트로의 확장: 학회 최우수상 '물탱크' 탄생의 씨앗

이 국시실 퀴즈 시스템을 매일 접하며 공부하던 학부생 팀(홍예은 학생 외)은 한 걸음 더 나아갔습니다.
"교수님, 입실할 때 5문제만 푸는 게 아니라, 등하교 지하철이나 버스 안에서도 저희끼리 1,139개 기출문제를 오답노트처럼 풀 수 있는 앱을 만들면 안 될까요?"

학생들의 아이디어에 바이브 코딩 개발 방법론과 Supabase 아키텍처 노하우를 지도했습니다. 학생들은 스스로 기출문제를 체계화한 웹앱 '물탱크'를 성공적으로 런칭했고, 이 결과물은 2026 대한지역사회물리치료학회 추계학술대회에서 4년제 대학들을 제치고 최우수상(1위)을 거머쥐는 쾌거로 이어졌습니다.

교수가 현장의 병목을 치료하기 위해 만든 작은 도구가, 학생들에게 영감을 주어 전국 학술대회 수상작이라는 결실로 확장된 것입니다.

7. 에필로그: 감시가 아닌 '성장의 울타리'를 짓는 바이브 코딩

기술을 도입할 때 가장 경계해야 할 것은 기술이 사람을 옥죄는 '감시 도구'로 전락하는 것입니다.

만약 제가 1,500만 원짜리 상용 솔루션을 사다가 CCTV와 얼굴인식기를 달았다면, 학생들은 자습실을 감옥처럼 느꼈을 것입니다.
하지만 "자신의 취약점을 마주하고, 5문제를 풀며 뇌를 깨우고, 안전하게 몰입할 수 있도록 돕는 시스템"이라는 교육적 진정성을 담았기에, 학생들은 불만 대신 자발적인 학습 의지를 불태웠습니다.

바이브 코딩은 단순한 웹사이트 제작 기술이 아닙니다. 교육자가 머릿속으로만 그리던 '이상적인 교육 환경'을 외주 개발사나 예산의 한계에 가로막히지 않고, 오늘 당장 실체화할 수 있게 만드는 강력한 날개입니다.
