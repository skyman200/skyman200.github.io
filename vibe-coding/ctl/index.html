1. 들어가며: "LMS를 왜 교수가 직접 만드나요?"

대학에는 이미 수천만 원에서 수억 원을 들여 도입한 상용 학습관리시스템(LMS)이 있습니다. 그런데 왜 현직 물리치료과 교수가 밤을 새워가며 3만 줄이 넘는 독자적인 LMS 웹앱 'CTL 실마리(CTL 학습 도우미)'를 직접 만들어 학생들에게 배포했을까요?

이유는 단순했습니다. 상용 포털은 '대학 실습 교육의 진짜 병목'을 단 하나도 해결해 주지 못했기 때문입니다.

  • 병목 1: 단순 출석 체크용 재생 바 — 상용 LMS는 학생이 영상을 틀어놓고 딴짓을 했는지, 아니면 핵심 관절 촉지 테크닉을 5초 단위로 10번 돌려봤는지 알려주지 않습니다. 과정 데이터가 없으니 개별 피드백이 불가능했습니다.
  • 병목 2: '영상 보며 필기'의 단절 — 학생들은 유튜브나 강의를 한 화면에 띄우고, 별도의 PDF 리더 앱을 켜서 창을 쪼개 필기하느라 인지 과부하를 겪었습니다. 필기 파일이 날아가거나 기기 간 동기화가 깨지는 사고도 빈번했습니다.
  • 병목 3: 과제 제출 마감 10분 전의 트래픽 폭격 — 한 학기 300명의 학생이 100MB가 넘는 실습 영상을 동시에 올리면, 대학 서버의 파일 업로드 제한에 걸리거나 서버가 뻗어버렸습니다.
  • 병목 4: 생성형 AI 과제 대필 검증의 부재 — 챗GPT 등장 이후 과제물에 복사·붙여넣기가 만연했지만, 교수가 일일이 대필 여부를 잡아낼 객관적 지표가 없었습니다.
"소프트웨어 엔지니어링의 본질은 도구의 화려함이 아니라, 사용자가 겪는 현실의 고통을 가장 가볍고 지속 가능한 방식으로 제거하는 데 있다."

저는 대학 예산에 손벌리지 않고 '서버비 0원(Zero Server Cost)'이라는 극단적인 제약 조건을 걸었습니다. 오직 Vercel, Supabase 무료 티어, YouTube 임베드, Google Drive API만을 조합해 동시접속 300명을 너끈히 견디는 프로덕션 엔터프라이즈 LMS를 완성한 실전 바이브코딩 기록을 공유합니다.

2. 전체 아키텍처 조감도: '식당과 주방'에 빗댄 0원 인프라

개발자 커뮤니티에서는 흔히 "서버비 0원으로 프로덕션 굴리려면 OCI(오라클 클라우드)에 리눅스 서버 띄우고 도커 올려야 한다"고 말합니다. 하지만 비개발자 교수에게 24시간 리눅스 서버 패치와 데이터베이스 백업은 재앙입니다. 시험 기간에 인스턴스가 멈추면 수업 전체가 마비되기 때문입니다.

저는 인프라 관리를 제가 하지 않고 글로벌 빅테크의 서버리스(Serverless) 무료 티어에 완전히 외주를 주는 분산 설계를 택했습니다.

구분 도입 기술 비용 해결한 역할 & 선택 이유
프론트/백엔드 Next.js 16 (App Router) + React 19 + Vercel 0원 주문 올 때만 0.1초 만에 켜지는 서버리스. 트래픽 폭증 시 자동 스케일아웃으로 절대 다운되지 않음.
데이터베이스 Supabase (PostgreSQL + RLS) 0원 Row Level Security로 학생 간 데이터 완벽 격리. RPC 함수를 통한 원자적(Atomic) 데이터 처리.
영상 스트리밍 YouTube 미등록(Unlisted) 임베드 0원 기가바이트 단위의 고화질 실습 영상 스트리밍 대역폭 비용을 전 세계 최고 인프라에 0원으로 위임.
대용량 과제 Google Drive API (Resumable Upload) 0원 학생 브라우저에서 교수 구글 드라이브로 직접 청크 업로드. Vercel 서버리스의 4.5MB 제한 완전 우회.
실시간 관제 Discord Webhook & Bot (`/현황`) 0원 질문 인입 즉시 교수 폰으로 0초 알림. 매일 07:00 미학습자 리포트 자동 발송.

3. 기술 난제 1: 5초 단위 시청 분석 엔진과 '영상 보며 필기' 분할 레이아웃

① 5초 단위 구간 분석: "어디서 멈추고 되돌렸는가?"

단순히 '재생 시간 45분 / 45분 완료'라는 숫자는 교육적으로 아무런 가치가 없습니다. CTL 실마리는 YouTube IFrame API와 연동해 5초 단위 비트마스크/버킷 버퍼링 알고리즘을 작동시킵니다.

  • 학생이 영상을 1.5배속으로 보는지, 건너뛰기(Seek)를 했는지, 특정 15초 구간을 4번 연속 리플레이했는지를 5초 슬롯 단위로 기록합니다.
  • 이 데이터는 Supabase의 시청 분석 테이블에 압축 적재되며, 교수의 대시보드에서 '반 전체 구간별 시청 히트맵'으로 시각화됩니다.
  • 교수는 강의실에 들어가기 전, "아, 12분 30초 대퇴신경 촉지 부위에서 학생들이 일제히 되감기를 했구나"를 미리 파악하고 그 지점부터 집중적으로 실기 지도를 시작합니다.

② 영상과 유인물의 심리스 분할: "영상 보며 필기"

가로 화면에서는 왼쪽 50%에 영상 플레이어가, 오른쪽 50%에 PDF 교재가 배치됩니다. 가운데 경계선(Divider Handle)을 마우스나 손가락으로 드래그하면 영상과 유인물의 너비 비율이 실시간으로 조절되며, 이 비율은 localStorage에 저장되어 다음 접속 시에도 그대로 복원됩니다.

특히 '학습 시간 분리 측정 엔진'을 내장했습니다. 영상을 재생하는 시간과 유인물을 읽는 시간을 완전히 독립된 타이머로 분리하고, 2분 동안 마우스나 터치 조작이 없으면 자동으로 타이머가 멈춥니다. 화면만 켜놓고 잠드는 허위 학습 시간을 원천 차단하기 위함입니다.

4. 기술 난제 2: 브라우저 언로드 64KB 한계를 뚫은 '델타 동기화' 필기 엔진

태블릿에서 애플펜슬이나 손가락으로 PDF 교재 위에 밑줄을 긋고 메모하는 기능은 필수였습니다. 그러나 가장 큰 난관은 '데이터 유실 방지'였습니다. 학생들은 필기를 마친 뒤 얌전히 [저장] 버튼을 누르지 않습니다. 그냥 브라우저 탭을 닫거나 다른 앱으로 전환해 버립니다.

① `sendBeacon`의 64KB 페이로드 한계

브라우저가 닫히는 순간(unload / pagehide 이벤트) 서버로 데이터를 쏘는 유일하게 안전한 API는 navigator.sendBeacon()입니다. 하지만 sendBeacon은 최대 64KB라는 엄격한 쿼터가 있습니다. 10페이지가 넘는 교재에 필기 스트로크(Stroke) 좌표를 가득 채우면 JSON 크기가 수백 KB로 폭증하여 저장이 거부됩니다.

② 델타 패치(Delta Patch)와 로컬 퍼스트(Local-First) 동기화

이 문제를 해결하기 위해 '로컬 퍼스트 델타 동기화 시스템(src/lib/annotation-sync.ts)'을 직접 설계했습니다.

  1. IndexedDB 선반영: 학생이 선을 긋는 즉시 브라우저 로컬 저장소에 0.01초 만에 캐싱합니다. 인터넷이 끊기거나 창이 강제 종료되어도 기기 안에 필기가 온전히 남아 있습니다.
  2. 체인지셋(Changeset) 추적: 서버와 마지막으로 동기화된 타임스탬프 이후에 새로 추가된 선, 수정된 텍스트 메모, 삭제된 객체 ID만을 모아 PATCH 패킷을 만듭니다.
  3. 초경량화: 전체 필기가 아니라 변경분만 전송하므로 페이로드 크기가 보통 2~5KB로 줄어들어 sendBeacon의 64KB 한도에 절대 걸리지 않습니다.
  4. 다중 기기 타임스탬프 충돌 병합: 스마트폰에서 줄을 긋고 아이패드에서 메모를 추가해도, LWW(Last-Write-Wins) 및 키 기반 병합 알고리즘(unit_annotations_merge.mjs)을 통해 서로의 필기를 덮어쓰지 않고 완벽히 합쳐집니다.
// annotation-sync.ts: 브라우저 언로드 시 64KB 한도를 방어하는 델타 패치 로직
window.addEventListener("visibilitychange", () => {
  if (document.visibilityState === "hidden") {
    const delta = getUnsavedAnnotationDelta(documentId);
    if (!delta || delta.operations.length === 0) return;

    const payload = JSON.stringify(delta);
    if (payload.length < 60 * 1024) {
      // 64KB 이하: 비동기 Beacon으로 즉시 안전 전송
      navigator.sendBeacon("/api/annotations/delta", payload);
      markDeltaAsSyncedLocally(delta.version);
    } else {
      // 비상 시: IndexedDB에 오프라인 플래그를 찍고 다음 앱 오픈 시 자동 복구
      persistPendingSyncToIndexedDB(documentId, delta);
    }
  }
});

5. 기술 난제 3: 500MB 과제 브라우저 직접 업로드와 AI 대필 판정

① Vercel의 4.5MB 페이로드 한계 우회

Vercel 서버리스 함수는 클라이언트 요청 바디(Body) 크기가 최대 4.5MB로 제한됩니다. 500MB에 달하는 학생들의 고화질 환자 평가 실기 영상을 백엔드로 직접 받으려면 수십만 원의 엔터프라이즈 요금제를 결제해야 합니다.

CTL 실마리는 Google Drive Resumable Upload API를 활용해 이 벽을 허물었습니다.

  1. 학생이 파일을 선택하면, Next.js 백엔드는 구글 서비스 계정 인증을 거쳐 Google Drive의 1회용 분할 업로드 URL만 발급해 학생 브라우저에 넘겨줍니다.
  2. 학생 브라우저는 Vercel 서버를 1바이트도 거치지 않고 Google Cloud 서버로 직접 500MB 영상을 청크(Chunk) 단위로 전송합니다.
  3. 업로드가 완료되면 구글 드라이브 파일 ID만 Supabase DB에 기록됩니다. 서버 트래픽 비용과 대역폭 부하는 완전히 0원이 됩니다.

② 생성형 AI 과제 대필 검사 파이프라인

학생이 제출한 과제(HWPX, PDF, DOCX, PPTX)는 백엔드 워커에서 텍스트를 즉시 추출합니다. 그리고 다음 두 가지 레이어를 통과합니다.

  • 레이어 1 (문체 통계 지표): 텍스트의 어휘 다양도(Type-Token Ratio), 문장 길이의 표준편차(Perplexity 분산), 한국어 상투적 AI 접속사("요약하자면", "살펴보겠습니다", "중요한 역할을 합니다")의 출현 빈도를 수학적으로 분석합니다.
  • 레이어 2 (AI 분류기 추론): 추출된 본문의 핵심 논증 구조를 소형 경량 LLM에 전달해 AI 작성 가능성을 3단계(낮음 · 보통 · 높음)로 분류하고 의심 근거 문장을 추출합니다.

이 판정 결과는 학생 화면에는 절대 노출되지 않으며, 교수의 채점 화면에만 참고용 배지(Badge)와 인용구로 조용히 표시됩니다. 교수는 불필요한 감정 소모 없이 사실에 기반해 학생을 지도할 수 있습니다.

6. 운영 난제: Discord 봇을 활용한 0초 교수 알림 & 일일 자동 리포트

시스템을 만들어도 교수가 매시간 로그인해서 질문을 확인해야 한다면 그것 또한 행정적 피로입니다. CTL 실마리는 교수가 사용하는 업무 메신저인 Discord와 완벽히 결합되었습니다.

  • 0초 즉시 알림: 학생이 실습 영상을 보다가 특정 시간대를 찍어 질문을 등록하면, 1초 만에 교수의 스마트폰 Discord 비공개 채널에 알림이 울립니다. "[물리치료 2분반 홍길동] 14분 20초 슬개골 가동술 방향 질문"
  • 디스코드 현장 답변: 교수가 이동 중에 Discord 앱에서 바로 답글을 달면, 학생의 웹앱 화면에 실시간 웹소켓으로 답변이 꽂힙니다.
  • 매일 아침 07:00 학습 리포트: 어제 접속한 학생 수, 시청 시간 상위 학생, 일주일간 로그인하지 않은 학생 명단이 자동으로 집계되어 디스코드에 보고됩니다. 교수는 리포트 하단의 [독려 보내기] 버튼을 눌러 미학습 학생들에게 즉시 앱 푸시와 알림 메일을 발송합니다.

7. 에필로그: 계획서가 아닌 '실제 돌아가는 플랫폼'이 증명한다

많은 분들이 바이브 코딩(Vibe Coding)을 "간단한 장난감 웹사이트나 만드는 유행"으로 치부하곤 합니다. 하지만 현장의 구체적인 고통을 가장 잘 아는 도메인 전문가(교수)가 명확한 아키텍처 원칙을 가지고 AI와 협업할 때, 외주 개발사 수천만 원을 주고도 못 만들 상용 서비스급 플랫폼이 탄생합니다.

"페이퍼 플랜(Paper Plan)으로 시작하는 연구는 현장을 바꾸지 못합니다. 300명의 학생이 이미 매일 접속해 공부하고 있는 '동작하는 플랫폼' 위에서만 진짜 살아있는 교육 데이터와 연구가 나옵니다."

CTL 실마리는 단순한 교내 과제 제출함을 넘어, 2027년도 과학기술정보통신부 기초연구사업(기본연구A)의 핵심 실증 테스트베드로 진화하고 있습니다. 학생들의 시청 로그, 필기 반응, AI 튜터 힌트 수용률을 과학적으로 분석하여 'AI가 어떻게 인간의 실습 학습을 돕고 비용을 최적화할 수 있는가'를 입증하는 국가 R&D의 든든한 기반이 될 것입니다.

코딩 문법을 몰라도 괜찮습니다. 당신의 머릿속에 있는 '현장의 병목'을 정확한 문장으로 적어 AI에게 건네보세요. 당신의 교실을 바꿀 다음 시스템이 바로 그곳에서 시작됩니다.
