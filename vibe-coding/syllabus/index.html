Vibe Coding Series · Ep.4

[바이브 코딩 실전기 4편] 37개 학과 759개 과목을 5일 만에 바꾼 비결: Cloudflare Pages와 Apps Script로 구축한 대학 강의계획서 AI 4주 적용 1초 체크 시스템

복잡한 인프라나 대규모 예산 없이, 비전공자 교수가 AI 에이전트와 대화하며 대학 전체의 행정 병목을 해결한 서버리스 3단 분산 아키텍처와 트러블슈팅 전말

작성자 김강훈 (동의과학대학교 물리치료과 학과장 · DIT AI 허브센터 팀장)
게시일 2026-11-10
🚀 실시간 시스템 바로가기: dit-ai4-check.pages.dev ↗

1. 들어가며: 대학 전체의 행정 병목을 마주하다

2026학년도 2학기, 동의과학대학교는 교육부 AID 사업의 일환으로 "전체 학과 교과목 대상 생성형 AI 4주 수업 적용"이라는 혁신적인 과제를 추진했습니다.

하지만 현장의 현실은 만만치 않았습니다:

  • 대상 규모: 37개 학과, 총 759개 교과목.
  • 기존 방식의 병목: 759개 한글(HWPX) 강의계획서를 각 교수님께 이메일로 발송 → 교수님이 주차별 계획을 일일이 수정 → 학과 조교 취합 → 교무처 검토 및 반려/재수정.
  • 예상 소요 시간: 최소 3~4주, 수백 건의 이메일과 전화 문의 폭주.

코딩 한 줄 모르는 비전공자 교수였지만, AI 코딩 에이전트와 대화하며 일하는 바이브 코딩(Vibe Coding)을 통해 이 문제를 단 5일(2026-09-05 ~ 09-10) 만에 해결하는 전용 웹앱 dit-ai4-check.pages.dev를 직접 기획하고 배포했습니다.

결과는 놀라웠습니다. 복잡한 로그인도, 별도의 매뉴얼도 없이 교수님들이 스마트폰이나 PC에서 1초 만에 자기 과목을 조회하고, 클릭 몇 번으로 AI 주차를 반영해 확정 PDF를 자동 생성하는 시스템이 완성되었습니다.

2. 시스템 구조: 가볍고 강력한 분산 아키텍처

대학 전산망에 종속되지 않고, 수백 명의 동시 접속을 버텨내기 위해 서버리스 기반의 초경량 구조를 설계했습니다.

교수님 브라우저 (PC · 스마트폰)
 ├─ UI/UX 화면 ──────▶ Cloudflare Pages (dit-ai4-check.pages.dev)
 │                     - index.html 단 한 장 (빌드 도구 없음, 초고속 로딩)
 │                     - 학과별 JSON 데이터 38개 분산 캐싱
 │
 └─ 저장 및 제출 ────▶ Google Apps Script 웹앱 (V8 엔진)
                       ├─ 과목별 확정 강의계획서 PDF 실시간 생성 (3건 병렬)
                       ├─ 구글 드라이브 '결과받기/학과명/' 폴더 자동 분류 저장
                       └─ 동시 제출 잠금(Lock) 및 캐시 무결성 관리

GitHub Actions (백그라운드 자동화)
 ├─ 30분 주기: 구글 드라이브 결과 폴더를 읽어 학과별 '제출완료' 배지 실시간 갱신
 └─ 데이터 변경 시: Apps Script 서버 캐시 자동 예열 및 비우기

왜 이 기술 조합인가?

  1. Cloudflare Pages: 대학교 네트워크의 방화벽이나 스마트폰 인앱 브라우저에서도 지연 없이 0.1초 만에 첫 화면이 열립니다.
  2. Google Apps Script: 대학 교직원들이 일상적으로 사용하는 구글 드라이브와 완벽하게 연동되며, 별도의 서버 비용 없이 안전하게 PDF를 생성하고 공유합니다.
  3. GitHub Actions: 교무처 직원이 드라이브 폴더를 일일이 열어보지 않아도, 메인 화면에서 37개 학과의 제출 진행률을 30분마다 자동 집계합니다.

3. 핵심 UI/UX: 사용자의 결정권을 존중하는 3가지 선택지

바이브 코딩으로 행정 시스템을 만들 때 가장 경계해야 할 것은 "AI가 모든 것을 마음대로 결정하는 것"입니다. 현장 교수님들의 전문성과 자율성을 보장하기 위해 세심한 3단계 인터랙션을 설계했습니다.

① AI 적용 대상 여부는 교수가 직접 판정

  • 이미 AI가 충분히 반영된 과목은 초록색 적용완료로 고정.
  • 현장실습, 졸업작품 등 구조상 불가능한 과목은 빨간색 적용불가.
  • 나머지 모든 과목은 담당 교수님이 직접 라디오 버튼으로 적용 대상 여부를 선택합니다.

② 맞춤형 3대 적용 방식 제공

  1. 개선안 그대로: 교무처와 AI허브센터가 연구하여 제안한 표준 AI 적용안을 원클릭으로 수용.
  2. 주차별 선택 체크: 15주 전체에 AI 연계 커리큘럼을 채워 두고, 원하는 주차(예: [권장 4주만] 버튼 클릭 시 1·5·10·14주 자동 선택)만 체크하여 반영.
  3. 본인이 직접 완성: 기존 강의계획서 텍스트를 인라인 에디터로 열어 자신의 연구 분야에 맞춰 자유롭게 커스텀 편집.

③ Before & After 나란히(Side-by-side) 실시간 비교

교수님들이 가장 불안해하는 것은 "내 강의계획서가 어떻게 바뀌었는가"입니다. [before→after 전체 강의계획서 보기] 버튼을 누르면, 왼쪽에는 기존 원본이, 오른쪽에는 AI 4주 반영본이 양옆으로 나란히 펼쳐지며 변경된 주차가 주황색 하이라이트와 [AI 연계] 태그로 즉각 시각화됩니다.

4. 실전 현장에서 건져 올린 트러블슈팅 교훈

코드를 직접 짜지 않더라도, 실제 배포 운영 과정에서 마주치는 버그를 AI에게 명확히 전달하고 해결하는 것이 바이브 코더의 핵심 역량입니다.

① 학교망과 구글 다중 로그인 충돌 ("Failed to fetch")

현상: 학교 전산망, 스마트폰 카카오톡 인앱 브라우저, 개인 구글 계정과 학교 계정이 겹친 환경에서 제출 시 fetch failed 에러가 발생했습니다.

해결: 표준 fetch 대신 XMLHttpRequest 우선 처리 및 JSONP 폴백 로직을 구축하고, 네트워크 자가 진단 페이지(check.html)를 별도로 제공해 실패율을 0%로 만들었습니다.

② 로컬 스토리지 부분 저장 유실 방지

현상: 여러 주차 중 한 주차만 수정하고 저장했을 때, 나머지 주차 데이터가 undefined로 덮어씌워지는 문제가 나타났습니다.

해결: 반드시 15주 전체의 골든 데이터를 먼저 로드한 뒤, 사용자가 변경한 델타(Delta) 주차만 오버레이하는 불변성 패치 패턴을 프롬프트로 지시하여 데이터 무결성을 확보했습니다.

③ 폐강·미개설 31과목 라이브 대조

현상: 학사 시스템(NDS)의 단순 상태값만 믿고 과목을 제외했다가, 분반 개설된 31개 과목이 누락될 뻔한 위기가 있었습니다.

해결: AI 코딩 에이전트에게 "가설을 세우고 실제 시간표 데이터와 교차 검증하라"고 지시하여 학과별 실제 강의 시간표와 100% 일치하도록 정합성을 검증했습니다.

5. 그대로 따라 만드는 바이브코딩 실전 통합 프롬프트

동일한 행정 혁신 웹앱을 만들고자 하는 교육자 및 개발자를 위해, 실제 개발 시 사용했던 통합 프롬프트 구조를 공개합니다:

[학교 강의계획서 기준 문서]를 기준으로, 학과 교수님들이 자기 과목의 "생성형 AI 4주 적용"을 온라인으로 체크·제출하는 웹앱을 만들어라.

1. 접근성:
- 별도 로그인 없이 열리며 37개 학과 목록이 카드로 노출된다.
- 학과 클릭 시 해당 학과 과목 표(과목명, 담당 교수, 전체 주수, 판정 상태) 표시.
- 학과별 [제출완료] / [수정 필요 N] 배지 표시.

2. 판정 및 편집:
- "AI 적용 대상"과 "적용 불가"는 반드시 사용자가 직접 고른다.
- 적용 대상 선택 시 3가지 옵션 제공:
  ① before→after 개선안 그대로 적용
  ② 주차별 선택 체크 (15주 중 체크된 주차만 반영, [권장 4주만] 원클릭 버튼)
  ③ 본인이 직접 완성 (기존 계획서 인라인 텍스트 편집)
- before(기존)와 after(AI반영) 전체 강의계획서를 나란히 비교하며 변경 주차는 색상 하이라이트.

3. 저장 및 PDF 생성:
- 과목별 [이 과목 저장] 지원 (부분 저장 및 타 교수 작성분 보존).
- 최종 [동의 후 제출] 시 Google Apps Script를 통해 구글 드라이브 '결과받기/학과명/'에 과목별 확정본 PDF 실시간 생성.
- 재제출 시 기존 PDF를 덮어쓰고 최신본만 보존.

4. 기술 스펙:
- 프론트엔드: Cloudflare Pages 정적 웹앱 (단일 index.html, Pretendard 글꼴, 무프레임워크)
- 백엔드: Google Apps Script 웹앱 (V8)
- 자동화: GitHub Actions로 30분마다 드라이브 스캔 후 제출완료 배지 갱신
- 학교망, 모바일, 다중 로그인 환경 대응 네트워크 재시도 및 접속 점검(check.html) 탑재.

6. 마치며: 코딩을 몰라도, 대학의 일하는 방식을 바꿀 수 있다

기술은 목적이 아니라 도구입니다. 759개 과목의 서류 작업을 교수님과 조교, 교무처 직원들이 며칠 밤을 새우며 메일로 주고받던 시절은 끝났습니다.

바이브 코딩은 복잡한 문법을 외우는 것이 아닙니다. "현장의 진짜 병목이 무엇인지 정확히 진단하고, AI 에이전트에게 올바른 아키텍처와 경계 조건을 제시하는 능력"입니다. 동의과학대학교의 이 실험이 전국의 수많은 대학과 공공기관에서 일하는 방식을 바꾸는 작은 불씨가 되기를 기대합니다.
